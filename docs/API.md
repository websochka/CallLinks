# Документация CallLinks API

CallLinks API — простой URL-based API для отправки номера телефона на смартфон, проверки баланса кредитов и перехода к пополнению. API подходит для интеграции с CRM, интернет-магазинами, внутренними панелями, WordPress, таблицами, helpdesk-системами и другими сервисами.

Базовый домен:

```text
https://calllinks.sochka.com
```

## Принцип работы

1. Пользователь устанавливает мобильное приложение CallLinks.
2. Приложение генерирует уникальный `TOKEN` устройства.
3. Внешняя система отправляет HTTP-запрос в CallLinks API с номером телефона и `TOKEN`.
4. CallLinks отправляет push-запрос на смартфон.
5. На смартфоне открывается стандартный номеронабиратель с подставленным номером.
6. Пользователь вручную подтверждает звонок.

Важно: API не совершает звонок автоматически и не заменяет мобильного оператора.

## Авторизация

Отдельной регистрации или OAuth-авторизации для базового сценария не требуется. Привязка запроса к устройству выполняется через `deviceToken`.

`deviceToken` — секретный идентификатор устройства. Его нужно получить в мобильном приложении CallLinks и использовать в запросах API.

## Параметры

### `deviceToken`

Обязательный параметр.

Назначение:

Связывает API-запрос с конкретным смартфоном пользователя.

Пример:

```text
deviceToken=YOUR_DEVICE_TOKEN
```

Рекомендации:

- Храните токен как секрет.
- Не коммитьте токен в Git.
- Не вставляйте реальный токен в публичный JavaScript, если это можно избежать.
- Используйте переменные окружения для серверных интеграций.

### `number`

Обязательный параметр для отправки номера.

Назначение:

Номер телефона, который нужно передать на смартфон.

Примеры допустимых значений:

```text
+380501234567
050 123 45 67
(050) 123-45-67
380501234567
```

Номер можно передавать в текстовом формате. Сервис нормализует номер перед отправкой на смартфон.

## URL-кодирование

При передаче номера через URL его нужно кодировать. Особенно это важно для символа `+`, пробелов, скобок и других специальных символов.

Правильно:

```text
https://calllinks.sochka.com/push/send.php?number=%2B380501234567&deviceToken=YOUR_DEVICE_TOKEN
```

Нежелательно:

```text
https://calllinks.sochka.com/push/send.php?number=+380501234567&deviceToken=YOUR_DEVICE_TOKEN
```

Во многих средах знак `+` в query string может быть интерпретирован как пробел. Используйте стандартные функции кодирования:

- JavaScript: `encodeURIComponent(phone)`
- PHP: `urlencode($phone)` или `http_build_query(...)`
- Python: `urllib.parse.urlencode(...)`
- Node.js: `URLSearchParams`

## Метод: отправка номера на смартфон

```text
GET /push/send.php?number={phone}&deviceToken={token}
```

Полный URL:

```text
https://calllinks.sochka.com/push/send.php?number={phone}&deviceToken={token}
```

Назначение:

Передает номер телефона на смартфон, связанный с `deviceToken`.

Параметры:

- `number` — номер телефона.
- `deviceToken` — TOKEN устройства.

Ответ:

```text
42
```

Ответом является число оставшихся кредитов.

Пример c URL-кодированным номером:

```text
https://calllinks.sochka.com/push/send.php?number=%2B380501234567&deviceToken=YOUR_DEVICE_TOKEN
```

## Метод: проверка баланса

```text
GET /push/balans.php?deviceToken={token}
```

Полный URL:

```text
https://calllinks.sochka.com/push/balans.php?deviceToken={token}
```

Назначение:

Возвращает количество оставшихся кредитов для указанного `deviceToken`.

Параметры:

- `deviceToken` — TOKEN устройства.

Ответ:

```text
42
```

## Метод: пополнение кредитов

```text
GET /push/pay.php?deviceToken={token}
```

Полный URL:

```text
https://calllinks.sochka.com/push/pay.php?deviceToken={token}
```

Назначение:

Открывает страницу покупки или пополнения кредитов для указанного устройства.

Типичный сценарий:

Используйте эту ссылку в интерфейсе администратора или менеджера, если баланс кредитов низкий.

## Серверная интеграция

Серверная интеграция предпочтительнее frontend-интеграции, потому что `deviceToken` не попадает в публичный JavaScript.

Общий поток:

1. Frontend отправляет ID клиента или номер на ваш backend.
2. Backend получает номер из базы данных или из запроса.
3. Backend подставляет защищенный `deviceToken`.
4. Backend вызывает CallLinks API.
5. Backend возвращает пользователю результат или сообщение об отправке номера.

## Frontend-интеграция

Frontend-интеграция проще, но токен может быть виден пользователю в исходном коде страницы или в инструментах разработчика.

Используйте ее только если:

- это внутренний инструмент;
- доступ к странице ограничен;
- риск раскрытия токена приемлем;
- для интеграции используется отдельный токен.

## Обработка ответа

API возвращает текстовый ответ. Для методов `send.php` и `balans.php` ожидается число оставшихся кредитов.

Рекомендуемая логика:

- Если HTTP-запрос успешен, прочитать тело ответа как текст.
- Проверить, является ли ответ числом.
- Показать пользователю статус: номер отправлен, осталось `N` кредитов.
- Если запрос завершился ошибкой, показать понятное сообщение и предложить повторить действие.

## Рекомендации по интерфейсу

Для CRM и внутренних панелей удобно размещать кнопку рядом с номером телефона:

```text
[Позвонить] +380501234567
```

После клика:

- заблокируйте кнопку на время запроса;
- покажите статус отправки;
- после ответа покажите остаток кредитов;
- при ошибке разблокируйте кнопку и покажите сообщение.

## Ограничения и важные уточнения

- CallLinks отправляет номер на смартфон, но не нажимает кнопку вызова за пользователя.
- Реальный звонок выполняется через мобильную сеть или настройки телефона пользователя.
- `deviceToken` должен храниться как секрет.
- Нельзя публиковать реальные токены в примерах, issue, логах и публичных репозиториях.
- Для надежной передачи номера всегда используйте URL-кодирование.
